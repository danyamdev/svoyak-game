# Правила проекта

Эти правила применяются ко всему коду проекта «Своя игра».

## Комментарии

- Комментируй код там, где без пояснения сложно понять причину решения, игровое
  правило, ограничение или переход состояния.
- Добавляй комментарии к сложной игровой логике, расчёту очков и ставок,
  восстановлению состояния, undo, импорту SIQ/JSON и работе с медиа.
- Для публичных функций и сложных типов используй JSDoc, если описание контракта
  помогает их безопасно использовать.
- Не комментируй очевидные операции и не пересказывай код другими словами.
- При изменении логики обновляй связанный комментарий или удаляй его, если он
  больше не нужен.

## Стили

- Стили компонентов и функциональных модулей пиши только в файлах
  `*.module.scss`.
- Глобальные стили допустимы только для reset, шрифтов, дизайн-токенов и базовых
  правил документа.
- Импортируй CSS Module непосредственно в файл, который его использует.
- Не добавляй глобальные селекторы для локального компонента.
- Цвета, размеры и другие повторяющиеся значения выноси в дизайн-токены или
  SCSS-переменные.

## Структура модулей

Каждый компонент, функциональный модуль или экран размещай в отдельной папке.
Минимальная структура:

```text
session/
  session.module.scss
  session.ts
  index.ts
```

Если файл содержит JSX, используй расширение `.tsx`:

```text
session/
  session.module.scss
  session.tsx
  index.ts
```

Дополнительные файлы размещай рядом с модулем:

```text
session/
  session.module.scss
  session.test.ts
  session.types.ts
  session.tsx
  index.ts
```

- `index.ts` является публичной точкой входа модуля.
- Не импортируй внутренние файлы другого модуля в обход его `index.ts`.
- Тесты, типы и локальные утилиты храни рядом с кодом, к которому они относятся.
- Имена папок и файлов пиши в `kebab-case`.
- Один файл должен решать одну понятную задачу.

## Проверка изменений

Перед завершением задачи запускай:

```bash
yarn validate
```

Изменение считается готовым, когда линтеры, тесты, TypeScript и production-сборка
завершаются успешно.
